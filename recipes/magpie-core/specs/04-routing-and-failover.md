# 04 · 路由组、策略和故障转移

## REQ-040：建立模型路由组

- 优先级：核心。一个路由组是一列有序 Provider/model 或嵌套 group，向 Agent 暴露为单个 `group/<id>`。
- 用户可创建、复制、改名、排序成员、编辑策略、禁用或删除自己的组；可隐藏 Magpie 自动发现的组并恢复。两个 Provider 有同名模型时可自动发现候选组，用户仍可关闭自动组。
- 组支持 chat 模型或只用于决策的 decision-model 组，二者不得混为可聊天模型。Decision 组可供分类/decision endpoint 使用，但不列入 Agent 聊天模型列表。
- `listed=no` 时，只把组名暴露给 Agent 列表；组成员仍可被 Gateway 路由，直接请求 `provider/model` 仍可工作。Provider 的“仅经路由组”选项控制是否单独列出 Provider 模型。
- 固定原版隔离 Web 的新建组表单还提供匹配 `provider/model` 的通配符和 `re:` 正则模式，以纳入当前及后续模型；组可选择同时列出成员或只列出组。其界面说明见根配方 `ORIGINAL_WEB_BEHAVIOR.md`，持久化与动态更新仍须实测。
- 正常验收：Agent 选择 `group/opus-anywhere` 后，组内模型按配置作为可替代成员运行。
- 失败验收：组不存在、空组或环形嵌套引用被清楚拒绝，不能递归卡死。

## REQ-041：路由策略

- 优先级：核心。用户可选择本基线列出的策略，并且策略行为可在 Routing 页面解释：

| 策略 | 排序结果 |
| --- | --- |
| `smart`（默认） | 在仍有可用额度的订阅中，优先用额度最接近重置者 |
| `order` | 按组中配置顺序尝试成员；当前成员不能回答时才去下一个 |
| `rotate` | 每轮在可用成员间循环选择 |
| `usage` | 优先选择近期/当前周期使用量较少的成员 |
| `pace` | 按每小时还能使用的周额度估算优先级，优先用每小时可用周额度更多、先到重置点者，避免浪费即将重置的周额度 |
| `weight` | 按用户给每个成员的 1–1000 权重平滑分配请求；未显式设置的成员权重为 1 |
| `fast`（也接受 `fastest` / `speed`） | 按近期首 token 延迟和生成速度，优先选响应更快的成员 |
| Free first | 原版界面说明优先使用不消耗订阅额度或 credits 的成员，然后使用其余成员；每个成员按其自身账户/key 策略运行。具体识别与网关行为待隔离请求对照 |
| Manual | 原版界面说明每个请求使用用户在组卡片中选中的模型及其自身账户/key；失败时不自动换到其他成员。状态持久化与网关行为待隔离请求对照 |

- 单 Provider 的多个 key 可用同样的快速策略。无额度数据的普通 API key 由明确的顺序/最近服务结果决定，不得假设它有订阅配额。
- `stays` 控制一次会话绑定到 key/account：`auto`（依赖上游缓存时保持）、`session`、`turn`、`off`、`strict`。`strict` 即使账户额度耗尽也不切换，错误返回 Agent。
- 原版表单还提供受限成员保持位置或移到队尾、首响应等待、全部成员暂时不可用时的再次尝试窗口、组上下文窗口、思考等级与路由规则；具体默认值和说明见 `ORIGINAL_WEB_BEHAVIOR.md`，运行效果需要分别核验。
- 正常验收：`order` 组的 A 返回 429、B 返回 200 时调用顺序为 A、B，Usage 的最终请求是成功重试。
- 边界验收：weight=3 对 weight=1 的两个成员，在足够请求样本上约按 3:1 平滑分布；不能一次长批处理导致 4 连续偏置。

## REQ-042：选择可服务成员和 account 顺序

- 优先级：核心。每次选择依次排除：已暂停账号、明确不服务该模型的账号、已达到用户设置的 cap/预算账号；有 plan 模型限制时，仅在没有其它可服务账号时考虑受限模型账号；需要重新登录的账号留在列表但跳过且不标成额度耗尽。
- 对余下成员先应用 group/provider 策略，再按可配置的 sink 规则把刚被上游 429 rate-limit 的但仍有额度成员排到后面，再尝试 Provider fallback model，最后尝试暂时 resting 的成员。按使用记录和 retry 时间防止对硬失败成员连续打满。
- 额度窗口优先使用实际上游返回。付费账户优先级不因一次网络读取失败而突然变成无限额度。
- 正常验收：同一订阅两个账户中，一个模型计划不含该模型，另一个包含；请求必须优先选后者。
- 失败验收：账户刚在原生 App 中切换/注销、额度状态陈旧或权限不明时，显示状态未知或过期并跳过必要请求，不编造余额。

## REQ-043：按请求上下文匹配路由规则

- 优先级：核心。
- 路由组可包含规则：Agent、会话/项目文件夹、模型家族、提示词内容/意图、model effort、快速/普通模式、上下文窗口需要、当前预算和时间条件等。规则对调用者可解释，并显示命中原因。
- 支持按输入特征路由；只有在用户打开相应 decision/classifier 功能时才把请求摘要交给分类模型。分类问题可设置候选标签和有效输出校验；识别失败时使用明确默认规则或原组策略。
- 规则优先级确定且 UI 可调整；没有规则命中时回到组默认策略。Agent/目录编辑不会清除规则。
- 正常验收：对“fix the login bug”配置 bug 标签的 classifier 返回 `bug`，组路由选择 bug 成员，并能查看规则命中解释。
- 失败验收：classifier 返回未知 label、超时或被拒时不循环调用；保留原请求在指定 fallback 下运行或返回明确 classifier error。

## REQ-044：Session affinity 和重置

- 优先级：核心。
- 对有上游 prompt cache/session affinity 的 Provider，默认 `auto` 在同一会话中优先保留先前成功的账号/模型；多个请求不得因列表顺序变化无故切换。
- 客户端可用原生 session header 或 `X-Magpie-Session` 指定会话。远程/下游调用需保留 session id；路由历史按会话显示。
- 用户指定 `turn`/`off` 后解除会话粘性；设置 `session` 维持会话；`strict` 永远不跨账户，即使当前账户失败。
- 正常验收：连续两轮都在同一 session 且首个 Provider 可用时使用同一账户。
- 失败验收：没有 session id 时不根据 prompt 猜测会话；粘性缓存损坏时按明确默认策略而非任意 key。

## REQ-045：重试和 Fallback 边界

- 优先级：核心。
- 以下情况可触发组/账户 fallback：quota exceeded、rate limit、指定网络/上游暂时错误、不可达，或用户配置的模型 fallback。只对符合规则的错误重试。不可把内容拒绝/账号策略错误误判成可用额度耗尽。
- 每个尝试有次数/循环上限、超时、取消和退避；用户中断后停止后续尝试。不可把可能有重复副作用的请求任意重发；若重试不安全需报告。
- Anthropic/service-tier 兼容：请求 tier 与实际发送/上游返回 tier 的区别可观察；某计划不支持 ultrafast 时按明确降级规则使用 priority 或报错。
- 最终没有成员可用时，返回客户端可读的 429/上游错误并在 Routing 页面说明每个成员为什么未选。
- 正常验收：模型 A 429、模型 B 200，Agent 无感知切换；请求计一次成功并标记 retried。
- 失败验收：所有成员都拒绝 prompt 内容时，不把所有账户休眠多日；错误指出内容/模型拒绝类别。

## REQ-046：实时路由解释和历史

- 优先级：一般。
- Routing 页面有当前 live 状态，能显示 Agent 发出的请求、命中组/规则、当前正在尝试的成员、每个失败尝试及最终回答者。用户可隐藏账号 email。
- 历史按请求或 session 查看，说明成员顺序、尝试原因、最终状态、重试和成本估值。session 的标题使用本机可读名称；未知名称显示完整 ID，不虚构标题。
- 过滤项至少支持时间、Provider、model、account、agent、purpose、失败/重试、调用来源和 computer；请求和 session 视图都可切换。
- 正常验收：A 速率限制、B 回答后，live 视图先显示 A 的 rate limited，再显示 B answering/answered。
- 失败验收：日志不可读时标明不完整/未知，不显示空白为“没有请求”。

## REQ-047：System One / 模型决策

- 优先级：一般。
- 只用于决策的模型/组可被 `/v1/systemone` 或等效分类接口调用。Decision 模型组由自己的提供者与额度规则依序尝试，按安全限制处理选项与返回 JSON。
- 分类器作为路由的附加决策，不得把原始秘密和完整隐私数据发送到不必要的模型。用户能关掉自动决策，恢复静态顺序/默认策略。
- 正常验收：请求一个已定义 choices 的分类，返回其中之一并显示对应 route decision。
- 失败验收：无效 JSON、错误 choice 或上游超时时转为明确定义的 fallback，不把不可信输出当作模型 id/URL 执行。

## REQ-048：Web 搜索配置和 Provider 代搜

- 优先级：一般。
- 当 Agent 要求 web search 但模型不提供时，可依次用用户启用的 Provider search、Tavily、Brave、Exa、Firecrawl、You.com、DeepSeek、SearXNG 等服务。用户可配置顺序、每服务开关/多 key/轮换方式和 API base URL；最近被拒 key 延后。
- Tavily 额度可见于 Settings、Usage/CLI search。搜索服务关闭只禁用，不删除 key。错误/无结果后继续下一个已启用 searcher；全部失败才报告错误。
- 正常验收：第一个服务无结果，第二个返回结果，Agent 得到搜索结果。
- 失败验收：API key 被拒时不得永久删除它或错误报告为有效结果。

## REQ-049：Agent 工具服务

- 优先级：一般。
- 通过 MCP 暴露 `web_search` 和按 URL 读取页面的 `web_fetch`。根据用户所选模型、Provider/API 或订阅账户的实际能力提供图片理解、图片生成和视频生成/查询/内容读取；视频不能无依据地限定为仅订阅能力。可在 CLI `magpie tools` 查看并以 `magpie tool` 调用。
- 媒体任务保留创建时的上游 key/account 归属；查询与内容读取重新检查当前调用者的模型/账户权限。MCP job/file 的创建 Gateway KeyID 与直接 HTTP 视频任务的授权规则分别执行，不能混为同一种所有权。Gateway 包的 UPSTREAM_ROUTES.md 提供精确路径、返回形态及尚待采集的 schema；不从已有处理器推导未注册的列表、删除或 remix 操作。
- 工具参数要验证 URL、输入文本、尺寸、输出目录和文件名；媒体返回可保存到用户指定文件/目录。工具能力清单应由模型/Provider 实际支持情况生成。
- 正常验收：Agent 通过 MCP 搜索网页并收到标题/URL/摘要，`magpie tool generate_image ... -o file.png` 在成功后写出文件。
- 失败验收：MCP 未连接、模型不支持视觉或媒体 Provider 返回错误时，给可读错误并清理未完成临时文件。
