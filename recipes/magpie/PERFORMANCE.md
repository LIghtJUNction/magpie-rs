# 性能要求和证据口径

指标的计时边界、正确性门槛、首次基线到数值预算的制定过程，以及每轮优化的保留条件，见 [OPTIMIZATION.md](OPTIMIZATION.md)。该合同适用于全部递归组件和最终集成。

用户目标是满足全部功能时尽可能低内存、本体精简；启动、延迟、吞吐、RSS/峰值、安装体积的数字预算均未知。最低设备与典型规模未知。下面的数据规模仅是建议的可复现实验参数，不是用户承诺或合格阈值。

| 场景 | 输入与负载 | 记录 |
| --- | --- | --- |
| CLI | 独立运行 help/version、发现0/10/100个Agent配置fixture、JSON输出；冷/热各30次 | 可执行体积、耗时p50/p95、进程峰值RSS；短命CLI RSS不代表服务 |

## 0.1.0 实现子集基线（2026-10-28）

本轮在 Arch Linux x86_64、Intel i9-12900HX、24逻辑CPU、16GiB RAM 上使用 Rust/Cargo 1.99.0 测量。Release CLI 为 577,896 字节。CLI runner 每种情况 5 次预热、30 次实测，退出码和输出校验全部通过；RSS 来自 Linux `wait4` 峰值：

| CLI 场景 | p50 / p95（ms） |
| --- | ---: |
| `--version` | 1.509 / 1.731 |
| Agent 发现（合成 4KiB TOML） | 1.439 / 1.583 |
| JSON status | 1.366 / 1.487 |
| JSON config path | 1.855 / 2.089 |

历史 runner 的 fork/exec 峰值 RSS 最大约 14.11MiB，包含 exec 前 Python 子进程的驻留内存，不能当作 CLI 本身的峰值；后续需分离测量器开销。Fixture 不含真实配置或凭据；测试不代表冷页缓存启动，也没有覆盖 0/10/100 Agent 规模。

网关 runner 测量无 Provider/模型的 loopback 实例：30 次启动（3次预热）、60秒空闲内存观察、100次 `GET /v1/models`。绑定 p50/p95 为 0.662/0.753ms，健康检查为 0.889/1.045ms，模型目录就绪为 1.047/1.251ms；目录请求为 0.090/0.191ms，正确性错误 0。空闲 RSS/PSS 中位数为 2,976/779KiB，5线程、4个文件描述符；目录响应为合法空列表。

原始 JSON 与 runner/源码/二进制散列保存在源码子模块 `benchmark/results/cli-2026-10-28.json` 和 `benchmark/results/gateway-catalog-2026-10-28.json`，复现命令见 `generated/magpie-rs-source/benchmark/README.md`。测量只覆盖当前 CLI 及空目录路径；Provider 转发、流式、并发、Usage、GPUI、Android 和其它 CPU/系统仍未测量。用户未给绝对毫秒或内存预算，本基线不构成性能通过，也未做足够的交替 A/B 轮次来归因改进。

这些结果不替代表中完整工作负载。当前原型的线程数、队列上限和本次单机 RSS 都不能升级为完整产品的固定性能合同。


## 0.2.0 开发快照（2026-10-28）

CLI 为 647,616 字节。30 次/场景、5 次预热，全部退出码与合成输出校验通过；fork 到退出的 p50/p95（ms）依次为 version 3.518/9.988、Agent 发现 3.819/4.973、status 3.763/5.200、config path 3.855/4.750。主机 1 分钟负载约 21，不能与之前负载不同的基线直接归因比较。wait4 的 RSS 包含 exec 前 Python 子进程，仅是上界；分离测量器开销仍待完成。

配置目录负载为 3 个 Provider / 60 个模型，30 次启动、100 次请求和 60 秒空闲采样；模型请求零错误，目录就绪 p50/p95 为 2.430/3.004ms，请求为 0.374/0.708ms。空闲 RSS/PSS 中位数记录为 2,232/36KiB，5 线程、4 描述符。窗口中 RSS 有变化，未同步采集 Swap/Pss_Anon，不能把较低驻留数字当作内存优化收益。网关测量时主机负载约 12–17。

原始数据位于源码 `benchmark/results/cli-0.2.0-2026-10-28.json` 和 `gateway-catalog-0.2.0-2026-10-28.json`，记录全部样本、正确性、工具链与散列。相较 0.1.0 增加了真实配置目录功能，负载和输入源码散列口径也有变化，本轮没有声称性能门槛通过或优化胜出。

`benchmark/results/cli-0.2.0-2026-10-28-corrected-rss-v2.json` 使用分离的延迟/RSS两轮。每场景各5次预热、30次实测，共280次CLI启动零错误。GNU time的C子进程排除了Python父进程，保留加载器及C子进程exec前下限；没有扣减对照值。

|version|1.512 / 1.822|2.564|

64MiB父进程内存对照不会抬高空程序测量，16MiB触碰内存正对照会被计入；大输出、非零/信号退出和解析错误检查通过。工具版本、来源、散列、全部样本与包装器30组交替对照保留在JSON。主机有约30.8GiB swap使用和并发编译；未测冷启动、独立多轮、原版A/B或真实低内存设备。数字变化来自方法修正及主机条件，不能作为软件优化胜出。

## 本地短时转发基线（2026-10-29）

Linux x86_64，以独立合成 loopback Provider 和已构建 CLI `magpie 0.2.0` 运行；二进制 SHA-256 为 `e3463d7717d0f8a73b5ea6d63d363e9835ce1c81dc0afbdb5c83bbf3696b86f1`。每个矩阵格运行 5 秒，而不是 5 分钟：64 KiB JSON 与 16 KiB SSE、并发 1/4/16，校验完整内容、终止、取消及真实上游到达。直连与网关合计 3416 次成功、1228 次按当前网关 4 活跃请求上限拒绝、0 次错误；取消 5 次均为合成请求。

四并发 JSON p95 为 9.67 ms、有效吞吐约 79.99 次/秒；负载发生器按最多 20 轮/秒节流，这不是服务容量。目标进程 RSS 采样最大 5764 KiB、Swap 采样最大 0 KiB；采样间隔 p95 106 ms，不含 GPU、Python 测试端或未观察到的短命子进程。主机有其他负载且使用 swap。16 并发 SSE 成功 40、拒绝 120，暴露当前固定并发上限对功能和吞吐的限制。

汇总证据在源码子模块 `benchmark/results/forwarding-2026-10-29-short.json`；原始记录包含主机进程遥测，保留在工作区外，SHA-256 `62ceeaf5b4b81d0e1d4b904038f6d8549b8d2b317fd3ea75d241a0dc021f2496`。本次只建立旧转发子集短时参考，未测原版 A/B、外部服务、完整功能、300 秒流或五分钟负载，不能标任何完整产品预算通过。源码当时有并行未提交工作，不能用工作区哈希证明二进制由该工作区构建；按二进制散列识别该次结果。

该次运行器原始字节未保留，后续安全修订改变了运行器散列；现有结果可用于辨认这次测量，但不能声称能够逐字节重放。未来需要用已提交版本重新测量并记录构建来源。
