### max_tokens 兼容的精确合同

官方提交：[cae785a37aacff21fb84089ec80809240d7d61da](https://github.com/yetone/magpie/commit/cae785a37aacff21fb84089ec80809240d7d61da)（0.1.2155）。关键路径为 `internal/provider/token_field.go`、`token_field_test.go`、`test.go`、`internal/gateway/token_field.go`、`token_field_test.go` 与 `chat.go`。映射 REQ-031/032/033；模型测试也应最终使用同一规则，不能只修转译路径。

- 只对 Chat 上游生效。上游主机严格等于 `openai.com` 或以 `.openai.com` 为完整域后缀时，预先将单一 `max_tokens` 字段换为 `max_completion_tokens`；`notopenai.com`、`openai.com.example.org`、Azure、DeepSeek、Zhipu、普通 relay 都不能因为名称相似而套用这一主机规则。其他既有供应商专属适配独立保留。
- 兼容 relay 的重试不以主机为前提：上游确实返回 HTTP 400，且明确拒绝当前字段并要求改用另一字段时，才交换该顶层参数一次。数值太大、普通 invalid parameter、认证或额度错误、模糊提示都不是重放依据。
- 改名不能改变参数值、messages、tools、扩展字段和用户文字；出现两个字段时不得猜测优先级，不能静默删除其一。缺少该参数、非对象 JSON、不可解析错误均不触发兼容重放。
- 任一方向最多重试一次；第二次即使要求改回也终止。错误体读取有界，不把上游正文或 key 回显给调用者。已开始给客户端发送响应后不得再重放；SSE 200 中的错误事件不是 HTTP 400。
- 两次尝试共享请求总 deadline 和并发槽；取消、超时和服务关闭均可结束重试。只改变该上游请求，不改用户 ProviderStore 或 Agent 配置。
- 必须覆盖原生 Chat 与其他协议转到 Chat 的真实 HTTP fixture、成功 200、明确 400 两个方向、模糊/数值/401/429/500/双字段/无字段/二次400、域名伪装、取消/超时和流式已开始的边界。原版测试只用了伪上游，本轮 fixture 也不能写成真实 OpenAI 账户验收。
