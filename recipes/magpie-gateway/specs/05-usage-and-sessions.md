# 05 · 用量、额度、预算与会话

## REQ-050：汇总 Usage

- 优先级：核心。Usage 页面、Provider/account 卡和 CLI 统一显示 Gateway 收到的请求、模型、Provider/account、输入/输出 token、缓存读写 token、reasoning token、次数、成本估算、状态、重试和时间。
- Provider 提供的上游用量/额度与本机 Gateway 观察到的请求用量分开显示；二者来源和更新时间可辨认。缺失 token 或 pricing 时显示未知/估值，不显示为零。
- 跨 Provider 统一账单时保留原始模型 id 和定价币种；支持按一次请求的实际最终 Provider 展开请求尝试。
- Usage 不得默认收集/保留请求正文。系统能以 request ID 关联请求和 route trace，而不靠正文检索。
- 正常验收：一笔由上游响应返回 token 数量的成功请求，在 Provider、Model、Account 和总览上总计一致。
- 失败验收：一笔失败或已重试请求不会将失败尝试重复计入最终成功调用；用量未返回时标成 unknown。

## REQ-051：额度和窗口

- 优先级：核心。显示账户/API key 上游配额及窗口（每日、每周、每月/自定义重置），包含已用、可用、重置时间、更新时刻及可信状态；模型计划/订阅周期分别显示。
- 账户无 quota endpoint 时展示请求计量或“上游未提供”，不可伪造额度百分比。时间戳使用用户本地时区呈现，存储和接口使用明确时区。
- 用户可以手动刷新一个 Provider 或全部 quota；有 last-refresh 和 loading 状态。自动刷新遵守上游速率限制，失败后保留最后一次数据并标明 stale。
- 正常验收：CLI 与 Usage 卡读取同一 quota snapshot，额度和重置时间相同。
- 失败验收：离线刷新不把旧额度清零或显示为刚刷新。

## REQ-052：Cap、预算和计算

- 优先级：核心。用户可设置 key/account/Provider/Model 的每小时、每天、每周或周期上限，以及模型价格、预算/开销上限。拒绝前告知具体 cap 和重置点。
- 每次对话的 cap 需要聚合全部分页响应与工具步骤；本次请求成本可按已知定价估算。预算规则可作为组路由筛选条件。
- 额度消耗速率以当前有效窗口剩余额度除以到 reset 的时长计算；费用速率用历史账单/估算计算。界面写明使用的窗口和估值方式。
- 正常验收：设置某账户每日 cap 到 20 次后，达到第 20 次拒绝新请求并说明重置时间。
- 失败验收：价格表缺失、额度 endpoint 失败或币种未知时不误报“仍在预算内”。

## REQ-053：查询和分析

- 优先级：一般。Usage 支持时间范围（今天、周、月、自定义）、Provider、模型、account、Agent、purpose、请求结果、重试和入口来源筛选。
- 视图支持按日/周/月和 Provider/account/model 分组；显示请求数、token、重试/失败、上游成本估值和预算趋势。每个金额都可查看模型定价与来源。
- 显示 Gateway 当前并发、等待数、请求延迟、首 token 时间及 Provider 上游错误状态；未获得的指标不生成示例数替代。
- 正常验收：筛选指定 account/time 后，明细行和卡片汇总相符。
- 失败验收：自定义时间区间无数据时显示无记录与筛选上下文，不沿用旧图表数。

## REQ-054：Session 列表

- 优先级：一般。Session 页面展示从 Gateway 请求以及被识别的本机 Agent 会话合并的对话 session。每项展示 Agent、模型/组、来源、时间、请求数、最近状态/标题等可用元数据。
- session 标识来自 Agent 原生字段、配置路径与 request metadata 的稳定组合。相同 Agent 的子进程/不同电脑不能因名称相同而不加判断地合并。
- Session 可以搜索/过滤和按 Agent、时间、模型/组分类；CLI/UI 不可把不可访问的旧文件当作空 session。
- 正常验收：同一 Agent session 多轮 Gateway 请求列为一条 session，并显示 request count。
- 失败验收：缺少原生 session id 时显示“无法确认”并用可追踪的请求 id，不伪造可跨机器稳定的 id。

## REQ-055：消息内容、记录开关与保留

- 优先级：高（隐私敏感）。默认不记录任何 prompt/reply 正文。用户在设置中明确打开后，才可记录本机可获取的 prompt/reply 文本，并在 CLI/UI 标清录制来源与状态。
- 源码/文档基线配置为关闭；启用录制时，默认保留期 7 天且空间上限 256 MiB，以先达到者为准。用户可改变保留期/限制及删除记录；旧记录按照新策略清理。
- 正文保存到本机数据目录，不发送到遥测或远程 Provider。禁止正文、OAuth code、access/refresh token 和 Provider API key 写入普通日志。
- 显示摘要的 UI/搜索结果只用内容预览，不自动调用外部 embedding 服务。删除 session 时，其相关正文同步删除。
- 正常验收：默认新安装打开 Session 页面只见元数据，不见消息文本；用户开启后新请求可查阅，按 retain limit 删除。
- 失败验收：磁盘容量达到上限时停止记录/清理最旧数据并告知，Gateway 本身仍可以正常转发。

## REQ-056：隐私遮蔽

- 优先级：高。用户可启用 prompt masking，在实际发送至上游的 prompt 中替换符合规则的秘密字段/字符串。界面展示规则、状态和作用范围。
- 遮蔽规则版本、匹配/替换次数和目标可审计；不得在 GUI trace、错误日志或 Usage export 中保留被遮蔽原值。不能修改图片/audio 二进制或未覆盖的多模态载荷并声称已遮蔽。
- 用户可以对单规则临时关闭并看到提示；默认遮蔽规则不应误删普通自然语言。具体规则与敏感字段集应由配置决定。
- 正常验收：向上游的文本不再包含配置中匹配的明文，而本机可选明文记录的权限和保留策略明确。
- 失败验收：规则语法错误或遮蔽服务不可用时按 fail-closed 处理，提示用户，而非安静发送原文。

## REQ-057：Pricing

- 优先级：一般。维护模型输入、输出、cache、reasoning 价格、计价单位和币种；支持用户编辑自定义模型价格，并显示来源和最后更新时间。
- 支持由模型 ID 匹配价格目录；对新模型/自定义模型允许添加价格。公开定价更新失败时保留本地缓存并显示旧时间。
- 成本是按收到 token 或按估算价格计算的观测结果，不等同于最终发票。展示中不能把估算值写成上游已扣款金额。
- 正常验收：用户修改自定义模型价格后，过去数据可明确区分使用历史价格还是按新价格重算。
- 失败验收：未知模型 pricing 显示 `unknown`，不让费用图表以零误导。

## REQ-058：导出

- 优先级：一般。可将 Usage、请求行、quota history 和 sessions 导出为 CSV/JSON；使用当前筛选、明确时间范围和用户时区，支持合法字符与可读列名。
- 导出默认不包含 prompt/reply 正文、秘密或完整 key。用户如果显式导出正文，必须先检查录制功能和权限，并在导出文件确认其可能包含敏感内容。
- 正常验收：一份 CSV 在表格软件中打开时数据没有错位，汇总值与页面筛选结果一致。
- 失败验收：没有数据或写文件失败时给具体错误，不保留截断的成功文件。

## REQ-059：Quota/Usage API 与请求追踪

- 优先级：一般。HTTP API 与 CLI/UI 共享统一的 usage/quota/time 查询。提供前述 `/v1/magpie/usage*`、`/v1/magpie/quotas*` 以及 route/concurrency 查询。
- 请求明细区分 `completed`、`failed`、`retried` 和已取消/未知；每个 attempt 归属 actual provider/model/account。在使用 key scope 时按 key 权限过滤结果。
- 正常验收：控制台与 HTTP API 用相同筛选查询得到相同的聚合数。
- 失败验收：上游 usage 返回两次或使用两种协议时，去重依据是 request/attempt id，不是脆弱的内容相同判断。
